# 競馬予想

JRA全10競馬場の平地競走を対象に、馬の基礎能力と市場オッズを分けて計算し、勝率・適正オッズ・保守期待値を表示する白基調のPWAです。

## v4の考え方

近走、血統、馬場、コース、距離、枠、左右回り、脚質構成、騎手、馬体重、休養間隔、スタート、ラスト4F、当日の状態を基礎能力モデルで評価します。基礎評価にはオッズを入れず、最後の価値判定だけで市場確率と比較します。

市場確率を `q`、発走前に固定したv3勝率を `p` とすると、v4勝率は次の残差縮小式です。

```text
p4_i = q_i × (p_i / q_i)^0.8 / Σ[q_j × (p_j / q_j)^0.8]
```

- 対象は平地・新馬戦以外、1レース最大1頭の単勝のみ
- 発走1〜10分前に取得し、取得後2分以内に計算した時刻付き単勝オッズを使用
- オッズを10%下げ、2019年で固定した90%勝率下限から保守EVを計算
- 保守EVが+5%以上だけ仮想100円で前向き検証
- 利益ゲート通過までは実購入0円
- 解禁後も8分の1Kelly、1R資金0.25%、1日1%を上限とする

現在の公開ステータスは `data/forward-status.json` の `LOCKED` です。利益や的中を保証するものではありません。

## データの扱い

公開リポジトリに実在の出馬表や保存HTMLは同梱しません。利用者がJRA公式ページをHTML保存し、設定画面から読み込むと、ブラウザ内だけで解析してIndexedDBへ保存します。HTML、画像、スクリプトを外部送信しません。

HTML取込だけの場合、100点評価を確率へ換算した「参考勝率」を表示します。これはv3校正外なので、保守EVや購入判定には使いません。保守EVを有効にするには、発走前固定済みの全出走馬分 `v3WinProbability` と次のレース情報を含む正規化JSONが必要です。

```json
{
  "probabilityModel": {
    "version": "3.0.0-stable",
    "frozenBeforePost": true
  },
  "oddsSnapshotAt": "2026-08-15T09:55:00+09:00",
  "horses": [
    { "number": 1, "odds": 4.2, "v3WinProbability": 0.28 }
  ]
}
```

全馬のv3勝率合計が1でない、取得時刻が発走1〜10分前でない、オッズ取得から計算まで2分を超える、取消後の頭数が揃っていない場合は安全側へ停止します。

## 端末内HTML取込

1. WindowsのChromeまたはEdgeで、JRA公式の対象レース「詳細出馬表」を開く
2. `Ctrl+S` で「Webページ、HTMLのみ」として保存する
3. アプリの「設定」で前日版・当日最終版・参考表示を選び、保存HTMLを読み込む
4. レース後はJRA公式の「レース結果」を同様に保存し、参考表示・結果取込で精算する

前日版と当日版の最初の予想は発走前スナップショットとして固定され、結果後の再計算を過去成績へ混ぜません。同着、返還、取消は公式払戻データが揃わない場合に安全停止します。

## 対応特徴量

- 実装済み：近走、芝・ダート、距離、競馬場、左右回り、馬場状態、枠、脚質構成、騎手、斤量、馬体重、前走間隔、血統、調教師、追い切り、スタート、ラスト4F
- 任意入力：気温、風向・風速、筋肉評価、気温適性、風適性
- データが無い項目は推測せず中立値とし、充足度を下げる

## 開発・検証

```bash
npm ci --prefix uma-log-ai --ignore-scripts
node --check uma-log-ai/engine.js
node --check uma-log-ai/profit-engine.js
node --check uma-log-ai/jra-importer.js
node --check uma-log-ai/app.js
node --check uma-log-ai/learning-worker.js
node --test uma-log-ai/tests/*.test.mjs
node uma-log-ai/scripts/validate-race-data.mjs
```

静的ファイルのためビルドは不要です。リポジトリルートをWebサーバーで配信し、`/uma-log-ai/` を開きます。
