# うまログAI

東京・中山・京都の開催日全レースを対象に、近走・適性・枠順・騎手など10項目を100点満点で整理するスマホ向けPWAです。

## 実装済み

- 前日版と当日最終版を別スナップショットとしてIndexedDBへ保存（各版の締切より前だけ）
- 採点・順位・予想時オッズは最初の保存後に固定し、買い目予算は締切前の追記履歴として変更可能
- 10カテゴリの点数・充足度・評価理由・直近5走を表示
- `◎ ○ ▲ △ ☆ 消`、予想順位、自信度を算出
- オッズは参考表示のみ（採点・順位・買い目・予算配分から完全分離）
- 単勝、複勝、馬連、ワイド、馬単、三連複、三連単の買い目と100円単位の予算配分
- 確定結果との順位差、◎の的中、Top3一致、買い目的中、払戻・回収率を照合
- 発走前に保存できた予想だけを対象に、東京・中山・京都、芝・ダート、距離帯、券種ごとの累積成績を表示
- 発走前スナップショット付きの過去1年を開催日単位で60%・20%・20%に時系列分割し、検証・最終確認で悪化しない場合だけカテゴリ配点を更新
- 端末内JSONインポート、オフライン用PWAキャッシュ

## データについて

公開リポジトリには実在のJRAデータを同梱していません。初期表示は、実在の開催・競走馬・騎手・オッズではない架空デモです。

[JRAの利用条件](https://www.jra.go.jp/use/)と[JRA-VANの利用規約](https://jra-van.jp/info/rule.html)を確認しましたが、この公開Webアプリで利用できる無料公開APIや再配布許諾は確認できませんでした。JRA-VANには認定ソフト向けの例外もあるため、取得行為を一律に違法とは扱わず、許諾を確認できない自動取得・公開JSONへの転載を実装しない方針です。

実データは次のいずれかで接続します。

1. 利用者が正当に取得した正規化JSONを「設定」から端末内へ読み込む
2. 再配布許諾のあるプロバイダーを `UMA_LOG_DATA_URL` に接続する
3. 将来、法人向けライセンス済みバックエンドへ接続する

自動更新ワークフローは、リポジトリ変数 `UMA_LOG_DATA_URL` と `UMA_LOG_DATA_LICENSE_CONFIRMED=true` の両方が設定された場合だけ取得します。受信JSONには `source.redistributable: true` に加え、各特徴量がスナップショット時点で固定済みであるという提供元の保証 `source.asOfFieldsGuaranteed: true` が必要です。

## 開発・検証

```bash
node --check uma-log-ai/engine.js
node --check uma-log-ai/demo-data.js
node --check uma-log-ai/app.js
node --check uma-log-ai/learning-worker.js
node --test uma-log-ai/tests/*.test.mjs
node uma-log-ai/scripts/validate-race-data.mjs
```

静的ファイルのためビルドは不要です。リポジトリルートをWebサーバーで配信し、`/uma-log-ai/` を開いて確認します。
